# 国産み KUNIUMI — 星をつくる景観工房

地形・空・水を手軽に組み合わせて、壮大な風景や「星そのもの」をデザインするブラウザ用 3D 景観ソフト（Three.js）。
作った風景は glTF（.glb）・16bit ハイトマップ・Blender 用スクリプトで外へ持ち出せる。

## 起動

ES モジュールと Web Worker を使うので、`index.html` の直開きではなくローカルサーバーで開く。

- `start.bat` をダブルクリック（`py serve.py 5194` を起動してブラウザを開く）
- または `py serve.py` → http://localhost:5194/
  （`serve.py` は標準の http.server に no-cache を付けたもの。更新後に古いファイルが使われるのを防ぐ）

ライブラリは jsdelivr から読むので、初回はネット接続が必要：
Three.js r186、three-gpu-pathtracer 0.0.26、three-mesh-bvh 0.9.15、oidn-web 0.4.0（とその学習済み重み oidn-weights）。
一枚絵は **WebGPU** を使うので Chrome / Edge の最新版で開く。

### 一枚絵（実写調の静止画）

リアルタイム表示とは別の描画器で、同じシーン JSON を時間をかけて描く。

1. **地形を作り直す**：カメラに近いほど細かい区画（四分木）に分け、高さを直接計算して作る（最大 400 万〜700 万三角形）。
   ノイズ地形は設定の段数より細かい起伏まで、ハイトマップ地形は画像を滑らかに補間して画素より細かい小さな起伏を足す。
   区画の継ぎ目は縫い合わせて隙間を作らない。色は頂点ごとに塗る。
2. **空を光源にする**：空の物理モデル（Three.js の Sky と同じ式）で全天の HDR 画像を作り、太陽円盤ごと光源にする。
   太陽の柔らかい影、水や金属への映り込み、空からの青い間接光が物理的に出る。雲も空に描かれる。
3. **パストレース**（three-gpu-pathtracer / WebGPU）：反射・屈折・間接光・水の透過と吸収を計算する。
4. **AI ノイズ除去**（Intel Open Image Denoise / oidn-web）：少ないサンプル数でもなめらかにする。
5. **植生**：森になる場所（傾斜・標高・水際・群生のむら）に針葉樹と広葉樹を置く（10 万本規模、同じ形を位置だけ変えて並べる）。
   カメラが地面に近いときは足元に草の株も置く。遠くの森は地表の色（暗い緑）でも表すので、リアルタイム表示でも森の広がりが見える。
6. **空気**（GPU で後から重ねる）：
   - **厚みのある雲**：地図上の決まった位置にある雲の層（底の標高・厚みを設定）を光線で進み、雲自身の影、太陽側の縁の明るさ、
     遠くの雲のかすみを計算する。どこに雲があるかは 2D のノイズで決め、濃い所ほど頂が高く、3D のノイズで縁を削る
   - **雲の影**：地表の各点から太陽へ向かい、雲の層を通る量で日なたを暗くする
   - **立体的な霧と光の筋**：地表付近ほど濃い霧の中を光線ごとに進み、日光と空の光の散乱を足す。途中が地形・木・物体・雲の影なら
     日光は届かないので、山の陰や雲の切れ間から光の筋（薄明光線）ができる
7. **仕上げ**：光のにじみを加え、AgX（または ACES）でトーンマップ。

パネルの「一枚絵」で、幅・高さ・サンプル数・地形の精細さ・ノイズ除去・色調・露出補正・光のにじみを変えられる。
目安（Ryzen 5 5560U 内蔵 GPU）：1280×720・64 サンプルで準備 30〜40 秒＋描画 1〜2 分、1920×1080 なら描画 3〜6 分。
描いている間はリアルタイム表示を止めて GPU を譲る。

#### リアルタイム表示の空気

リアルタイム表示でも、一枚絵と同じ式の雲（厚みのある立体）・霧・光の筋を描く（`render/RealtimeAtmosphere.js`）。
シーンを HDR のまま画面外に描き、半分の解像度で各画素の光線に沿って雲と霧を計算して重ねる（歩数を減らし、ゆらぎで粗さを散らす）。
雲の影は地形・物体・水面の素材に差し込んで、太陽の直射だけを減らす（`render/cloudShadowPatch.js`）。
影の地図は地形・物体・太陽が変わったときだけ作り直す。この PC で 950×708 のとき 1 フレーム約 13〜21ms。

#### 太陽と空の明るさ

Preetham の空のモデルは、晴天でも直射日光と空の光が 1.3 : 1 ほどしかなく、影が薄く平板になる。
実際の晴天（およそ 5 : 1）に近づけるため、太陽円盤を 4 倍にしている（`skyModel.js` の `SUN_BOOST`）。
リアルタイム表示の太陽光（平行光源）もこの円盤の明るさから計算するので、両方の見え方がそろう。
明るさが物理的な値になったので露出は 0.1 前後が基準（以前の版のシーンは読み込み時に換算する）。
パストレーサは環境光を半精度（最大 65504）で持つため、照明用の全天画像では太陽円盤を広げて薄め、明るさの総量は保つ
（背景に見える太陽は本来の大きさ）。以前はここで切り詰められ、一枚絵の太陽が本来の約 27% になっていた。

#### 侵食

ノイズ地形には雨粒による水食（hydraulic erosion）を掛けている（「地形の性格」の「侵食」）。
谷筋・ガリー・扇状地ができ、削れた谷は岩肌、土砂のたまった所は土の色になる。
表示の解像度で形が変わらないよう、常に 513×513 の格子で計算し、その差分を各解像度へ足す。
| 物体パネル（右上） | 一覧、名前、位置・回転・大きさ、天体（かすみを受けない）、素材 |

### 物体と素材

- 形：球・立方体・円柱・円錐・角錐・トーラス・環（平たい環。惑星の環に）。大きさはメートルで、1 m〜100 km まで。
- 「天体」ボタンは、視線の先の遠く・画面の上寄りに直径が地形の 1.2 倍ほどの星を置く。天体はかすみで消えず、影も落とさない。
  環を同じ位置に置いて傾ければ、土星のような星になる。
- 素材は見本（石・苔むした岩・大理石・溶岩の星・青い惑星・ガス惑星・月・氷・黄金・鏡面・ガラス・恒星・市松・縞瑪瑙）から選び、
  模様（単色・大陸と海・ガスの縞・溶岩・大理石・岩肌・細胞・クレーター・縞・市松・画像）、色、細かさ、模様の種、凹凸、粗さ、金属、発光、透けを調整できる。
- 模様は手続き的に作るテクスチャ（色・法線・発光の 3 枚）。継ぎ目なく一周するので、球に貼っても縫い目が出ない。計算は Web Worker。
- 「画像」模様では手持ちの画像を貼れる（長辺 1024px に縮めてシーン JSON に埋め込む）。

作業中のシーンはブラウザの localStorage に自動で残る（消えても動作には影響しない）。
起動中は読み込み画面を出し、部品の読み込みに失敗したときや WebGL2 が使えないときは理由を表示する。
予期しないエラーは画面上部に知らせる。一枚絵を描いている間はファイルの読み込みや Delete などの操作を受け付けない（Esc で中止）。

## 設計：シーン = データ、描画 = その解釈

```
            ┌──────────── シーン JSON（src/core/schema.js）────────────┐
            │ terrain / water / sun / atmosphere / camera / render     │
            └───────────────▲───────────────────────┬──────────────────┘
       UI（ui/Panel.js）が  │ store.set(path)        │ subscribe(変更パス)
       パスで書き込むだけ   │                        ▼
                 ┌──────────┴──────┐   ┌────────────────────────────┐
                 │ core/store.js   │   │ render/RealtimeRenderer.js │ ← リアルタイム表示（今）
                 └─────────────────┘   │   Sky / Water シェーダ      │    歩き回るモード（予定）
                                       └─────────────┬──────────────┘
     core/（Three.js 非依存）                        │ 共通部品
       heightfield.js 高さ場の生成                   ▼
       terrainColor.js 地表色の焼き込み    three/terrainMesh.js  高さ場 → メッシュ
       png16.js        16bit PNG 読み書き  three/portableScene.js 標準 PBR だけのシーン
       sun.js          太陽・大気の計算      ├→ io/gltf.js       .glb 書き出し
       skyModel.js     空の HDR（CPU 版 Sky） render/StillRenderer.js 一枚絵（パストレース・ノイズ除去・空気遠近）
       terrainLod.js   近いほど細かい地形    workers/lodWorker.js
       erosion.js      侵食                  tonemap.js  AgX / ACES / Radiance HDR 書き出し
       objects.js      物体・素材の定義      three/objectLayer.js  物体 → メッシュ（表示と書き出しで共有）
       texgen.js       模様テクスチャの生成  three/TextureService.js 模様をワーカーで作り使い回す
     workers/terrainWorker.js（重い計算）    └→ 高画質一枚絵モード（予定：パストレーサ等の入力）
```

- **シーン JSON が正本**。描画器・書き出しはすべてこれを読むだけで、互いを知らない。
  一枚絵モードや歩き回るモードは「同じ JSON を別の描画器で解釈する」形で足せる。
- `core/` は Three.js に依存しない（ワーカーや Node でもそのまま動く）。
- 重い処理（ノイズ生成・ハイトマップ解釈・地表色）は Web Worker。計算中に来た変更は最新の1件にまとめる。
- 起伏の高さ・標高はメインスレッドで即座に形を変え、色は後追いで届く。
- 地表の色は CPU でテクスチャに焼く。リアルタイム表示と glb 書き出しで同じ絵になる。

### シーン JSON（version 1）の主な項目

| パス | 意味 |
|---|---|
| `terrain.mode` | `noise`（手続き生成）か `heightmap`（画像） |
| `terrain.size` / `resolution` | 一辺の長さ (m) / 頂点数（129・257・513・1025） |
| `terrain.heightScale` / `baseHeight` | 標高 = baseHeight + 正規化高さ(0..1) × heightScale |
| `terrain.noise.*` | seed・frequency（山の数）・octaves・persistence・lacunarity・ridged・warp・valley・falloff |
| `terrain.heightmap` | `{ id, name, png(16bit PNG の dataURL), width, height }` |
| `terrain.palette.*` | 低地・高地・岩・雪・水辺の色、雪線、岩の出る傾斜 |
| `vegetation.*` | trees（森の量）・treeHeight・conifer（針葉樹の割合）・grass（草）・seed |
| `water.*` | enabled・level (m)・color・distortion・waveScale |
| `sun.*` | elevation（度）・azimuth（北から東回りの度）・intensity |
| `atmosphere.*` | turbidity・rayleigh・mieCoefficient・mieDirectionalG・haze・exposure・ambient |
| `camera.*` | position・target・fov |
| `objects[]` | 物体。`{ id, name, type, position, rotation(度), scale(m), celestial, castShadow, material }` |
| `objects[].material` | `{ preset, pattern, color, color2, glowColor, scale, seed, bump, roughness, metalness, glow, transmission, image }` |
| `render.still.*` | 一枚絵の幅・高さ・サンプル数（Blender スクリプトにも渡る） |

同じ seed・同じ設定なら必ず同じ地形になる。解像度を上げると、格子で表せる細部だけが増える（大きな形は変わらない）。

### 座標の約束

- Y が上、**北 = −Z、東 = +X**、単位はメートル（glTF と同じ）。Blender では北 = +Y、東 = +X、上 = +Z になる。
- 高さ場とハイトマップ画像は **画像の上 = 北**。

## 他ソフトとの連携

### glTF（.glb）書き出し

| ノード | 中身 |
|---|---|
| `Terrain` | 地形メッシュ（法線・UV 付き）＋ 地表色テクスチャ（PNG 埋め込み）の PBR 素材 |
| `Water` | 地形の 3 倍の板。透過（KHR_materials_transmission）・屈折率 1.333・ボリューム吸収の水素材 |
| `Sun` | 平行光源（KHR_lights_punctual）。Blender の読み込みで W/m² に換算される強さで出力 |
| 物体の名前 | 物体ごとのメッシュ。模様は色・法線・発光テクスチャ（PNG 埋め込み）、発光は KHR_materials_emissive_strength、透けは transmission。同名は `_2` などで区別 |
| `Camera` | 透視カメラ（縦横比は「一枚絵」の幅・高さ） |
| scene.extras.`kuniumi` | シーン JSON 一式（埋め込みハイトマップ画像は除く） |

### glTF 読み込み

- KUNIUMI が書いた glb なら extras から設定を復元する。
- **地形は常にメッシュの形から取り込む**（真上からの正射影で各格子点の最高点を測る）。
  Blender で地形を彫り直して glb で戻せばそれが反映され、他ソフトで作った地形メッシュもそのまま地形になる。
  取り込んだ地形は「ハイトマップ」扱いになる。ノイズ設定は残っているので、生成方法を「ノイズ」に戻せば手続き地形に戻る。
- `Water`（名前に water/水）があれば水位に、平行光源があれば太陽の向きに、カメラがあれば視点にする。
- 物体は、ノードの extras（`kuniumiId`）か書き出し時の名前で見分けて地形から除き、位置・回転・大きさを読み戻す
  （Blender で動かした結果が反映される）。素材は KUNIUMI の設定（scene.extras）から復元する。
- Blender から書き出し直すときは「Include → Custom Properties」を入れると KUNIUMI の設定ごと戻せる。入れない場合は、いま開いているシーンの物体と名前で照合して位置を戻す（素材はいまのシーンのまま）。

### Blender でそのままレンダリングする

1. 「glb 書出」と「Blender 用 .py」を押し、2つを同じフォルダに置く（ファイル名はそろっている）。
2. Blender の Scripting タブでその .py を開いて実行（または `blender --python 名前_blender.py`）。
   - glb を読み込み、太陽の向きに合わせた物理空（Nishita / Multiple Scattering）をワールドに設定
   - 大気の濁り・青さを近似で反映、Cycles・解像度・サンプル数・カメラを設定
3. F12 でレンダリング。明るさはスクリプト冒頭の `SKY_STRENGTH`、空の太陽円盤を使うかは `USE_SKY_SUN` で調整。

スクリプトなしでも、glb を File → Import → glTF で読めば地形・水・太陽・カメラは入る（空だけが無い）。

### ハイトマップ（16bit PNG）

- グレースケール 16bit、画素値 0..65535 → 標高 `baseHeight .. baseHeight + heightScale`、画像の上が北。
- PNG の tEXt `kuniumi` に実寸（size・heightScale・baseHeight・waterLevel）を JSON で入れている。KUNIUMI で読み込むと実寸ごと復元される。
- Blender で使う場合：Grid（一辺 = size、細分多め）に Displace モディファイア、テクスチャにこの PNG（色空間 **Non-Color**、座標 UV）、
  強さ = heightScale、中間レベル = 0、オブジェクトの Z = baseHeight。
- World Machine・Gaea・Unreal・Unity など 16bit PNG ハイトマップを受け付けるソフトとも同じ形式でやり取りできる。

## 予定（次の段階の候補）

- 一枚絵：木の種類と季節（紅葉・枯れ木）、被写界深度、EXR 書き出し、複数ワーカーでの地形生成
- リアルタイム表示にも木を置く（歩き回るモードの準備）
- 歩き回るモード（地面に沿う一人称移動・速度切替）
- 高画質一枚絵モード（portableScene を入力にしたプログレッシブなパストレース、PNG/EXR 書き出し）
- 星としての表現：惑星の曲率・地平線の丸み、夜空と星々・衛星、雲、空気遠近の改善
- 地形：侵食、複数レイヤーの合成、ブラシでの手彫り、植生の散布
- 物体：小さな地形の塊（岩・浮島）、複数選択とグループ、ブーリアン、同じ物体の大量配置、模様の 3D 化（球の極の歪みをなくす）
- 連携：EXR ハイトマップ、Blender 側での霧（ボリューム）、glb に地表のマスク類も同梱

## 確認済みのこと・注意

- 植生・雲の影・霧：この PC で遠景・近景・逆光を描き、森（約 11 万本）、海面に落ちる雲の影、逆光で霧に伸びる島の影を確認。
  「外周の沈み」があるときは四辺の際を必ず海底まで下げる（正方形の縁が浅瀬で残ると水越しに直線の境目が見えたため）。
- 植生・細かい地形はノイズ地形とハイトマップ地形の両方で動く（ハイトマップで約 10 万本・300 万三角形を確認）。
- 一枚絵はブラウザ画面が隠れていても最後まで描ける（画面の描画に合わせて待つ処理を時間で待つ処理に変え、
  ノイズ除去が 90 秒で終わらなければ除去前の画像で仕上げる）。

- 一枚絵：この PC（Ryzen 5 5560U 内蔵 GPU、Chrome 系）で、遠景（空撮）・近景（物体つき）を描き、ノイズ除去と仕上げまで通ることを確認。
  WebGPU の既定のバッファ上限（128MB）では細かい地形が載らないので、GPU が許す上限まで要求している。
  GPU でエラーが出た場合は止めて理由を表示する。
- 全天画像から数値積分した太陽の明るさが、解析式と 0.1% 以内で一致することを確認（`skyModel.js`）。
- 格子で作る地形は、点ごとに計算できる形に組み替えた後も以前の版と完全に一致（リアルタイム表示の地形は変わらない）。

- 物体：創造パレットからの配置、クリック選択とギズモでの移動（シーンへの書き戻し）、素材の切り替え、画像模様、
  自動保存からの復元、glb の往復（7 種の形すべてで位置・回転・大きさ・素材が一致）、
  ノードの印が消え 1 つだけ動かした glb（Blender で編集した想定）でその 1 つだけ位置が変わることを確認済み。

- ブラウザ上で、glb の往復（標高誤差 平均約 0.3 m）、16bit ハイトマップの往復（実質無損失）、
  外部ソフト風の glb（中心ずれ・extras なし）と 8bit JPEG の読み込み、JSON の往復を確認済み。
- Blender スクリプトは Python の構文と、空の太陽方位の式（Cycles の定義）を確認済み。
  ただしこの環境に Blender が無いため、Blender 上での実行は未確認。初回は結果を見て `SKY_STRENGTH` を調整する想定。

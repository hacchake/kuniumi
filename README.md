# 国産み KUNIUMI — 星をつくる景観工房

地形・空・水を手軽に組み合わせて、壮大な風景や「星そのもの」をデザインするブラウザ用 3D 景観ソフト（Three.js）。
作った風景は glTF（.glb）・16bit ハイトマップ・Blender 用スクリプトで外へ持ち出せる。

## 起動

Node.js（24 以上）が必要。

- `start.bat` をダブルクリック（初回は部品を取り込み、開発サーバーを起動してブラウザを開く）
- または `npm install` → `npm run dev` → http://localhost:5194/

配布用に組み立てるとき：

| コマンド | 内容 |
|---|---|
| `npm run build` | `dist/` に組み立てる（部品・フォント・ノイズ除去の学習データをすべて同梱。外部への通信なし） |
| `npm run preview` | 組み立てた版を確かめる |
| `npm test` | 自動テスト（シーンの読み込みと換算、元に戻す、16bit PNG、地形の再現性と継ぎ目、太陽の明るさ、トーンマップ） |

組み立てた版はアプリとしてインストールでき（PWA）、一度開けばネットにつながっていなくても起動する
（日本語フォントは文字範囲ごとに分かれていて、使った分だけ後から保存される）。
GitHub では push のたびにテストと組み立てが走り（`.github/workflows/ci.yml`）、
Settings → Pages を「GitHub Actions」にしてから Actions の「Deploy to Pages」を実行すると公開できる。

部品の版は固定している：Three.js 0.186.0、three-gpu-pathtracer 0.0.26、three-mesh-bvh 0.9.15、oidn-web 0.4.0、oidn-weights 2.3.0-1。
一枚絵は **WebGPU** を使うので Chrome / Edge の最新版で開く。

表示は日本語と英語。ブラウザの言語で決まり、ファイル メニューの「表示言語」で切り替えられる
（`src/i18n/`。日本語の原文を鍵に英語を引く辞書なので、日本語の文言を変えたら辞書も合わせる）。

### 一枚絵（実写調の静止画）

リアルタイム表示とは別の描画器で、同じシーン JSON を時間をかけて描く。

1. **地形を作り直す**：カメラに近いほど細かい区画（四分木）に分け、高さを直接計算して作る（最大 400 万〜700 万三角形）。
   ノイズ地形は設定の段数より細かい起伏まで、ハイトマップ地形は画像を滑らかに補間して画素より細かい小さな起伏を足す。
   区画の継ぎ目は縫い合わせて隙間を作らない。色は頂点ごとに塗る。
2. **空を光源にする**：空の物理モデル（Three.js の Sky と同じ式）で全天の HDR 画像を作り、太陽円盤ごと光源にする。
   太陽の柔らかい影、水や金属への映り込み、空からの青い間接光が物理的に出る。雲も空に描かれる。
3. **パストレース**（three-gpu-pathtracer / WebGPU）：反射・屈折・間接光・水の透過と吸収を計算する。
4. **AI ノイズ除去**（Intel Open Image Denoise / oidn-web）：少ないサンプル数でもなめらかにする。
5. **植生**：森になる場所（傾斜・標高・水際・群生のむら）に針葉樹と広葉樹を置く（10 万本規模、同じ形を位置だけ変えて並べる）。
   カメラが地面に近いときは足元に草の株も置く。遠くの森は地表の色（暗い緑）でも表すので、リアルタイム表示でも森の広がりが見える。
6. **空気**（GPU で後から重ねる）：
   - **厚みのある雲**：地図上の決まった位置にある雲の層（底の標高・厚みを設定）を光線で進み、雲自身の影、太陽側の縁の明るさ、
     遠くの雲のかすみを計算する。どこに雲があるかは 2D のノイズで決め、濃い所ほど頂が高く、3D のノイズで縁を削る
   - **雲の影**：地表の各点から太陽へ向かい、雲の層を通る量で日なたを暗くする
   - **立体的な霧と光の筋**：地表付近ほど濃い霧の中を光線ごとに進み、日光と空の光の散乱を足す。途中が地形・木・物体・雲の影なら
     日光は届かないので、山の陰や雲の切れ間から光の筋（薄明光線）ができる
7. **仕上げ**：光のにじみを加え、AgX（または ACES）でトーンマップ。

パネルの「一枚絵」で、幅・高さ・サンプル数・地形の精細さ・ノイズ除去・色調・露出補正・光のにじみを変えられる。
目安（Ryzen 5 5560U 内蔵 GPU）：1280×720・64 サンプルで準備 30〜40 秒＋描画 1〜2 分、1920×1080 なら描画 3〜6 分。
描いている間はリアルタイム表示を止めて GPU を譲る。

#### リアルタイム表示の空気

リアルタイム表示でも、一枚絵と同じ式の雲（厚みのある立体）・霧・光の筋を描く（`render/RealtimeAtmosphere.js`）。
シーンを HDR のまま画面外に描き、半分の解像度で各画素の光線に沿って雲と霧を計算して重ねる（歩数を減らし、ゆらぎで粗さを散らす）。
雲の影は地形・物体・水面の素材に差し込んで、太陽の直射だけを減らす（`render/cloudShadowPatch.js`）。
影の地図は地形・物体・太陽が変わったときだけ作り直す。この PC で 950×708 のとき 1 フレーム約 13〜21ms。

#### 太陽と空の明るさ

Preetham の空のモデルは、晴天でも直射日光と空の光が 1.3 : 1 ほどしかなく、影が薄く平板になる。
実際の晴天（およそ 5 : 1）に近づけるため、太陽円盤を 4 倍にしている（`skyModel.js` の `SUN_BOOST`）。
リアルタイム表示の太陽光（平行光源）もこの円盤の明るさから計算するので、両方の見え方がそろう。
明るさが物理的な値になったので露出は 0.1 前後が基準（以前の版のシーンは読み込み時に換算する）。
パストレーサは環境光を半精度（最大 65504）で持つため、照明用の全天画像では太陽円盤を広げて薄め、明るさの総量は保つ
（背景に見える太陽は本来の大きさ）。以前はここで切り詰められ、一枚絵の太陽が本来の約 27% になっていた。

#### 侵食

ノイズ地形には雨粒による水食（hydraulic erosion）を掛けている（「地形の性格」の「侵食」）。
谷筋・ガリー・扇状地ができ、削れた谷は岩肌、土砂のたまった所は土の色になる。
表示の解像度で形が変わらないよう、常に 513×513 の格子で計算し、その差分を各解像度へ足す。

### 大陸と星（数千 km の大地）

- 大地の大きさは 200 m の箱庭から 1 万 km まで（「大きさ」は対数目盛り・km 表示）。高さ場の解像度は 4097 まで。
- **地球の地形の取り込み**（ファイル → 地球の地形（地名・緯度経度）…）：地名検索（OpenStreetMap Nominatim）・ひな形（日本列島・北米大陸・ヒマラヤなど 17 か所）・緯度経度と一辺の長さで範囲を選ぶと、
  公開されている標高タイル（Mapzen Terrain Tiles／AWS Open Data。SRTM・GMTED・ETOPO1 などを合成、海底地形も含む）を取り寄せて大地にする。
  下見の地図はドラッグで移動・ホイールで範囲の大きさ。取り込んだ地形は 16bit ハイトマップとしてシーンに入り、範囲と出典も `terrain.heightmap.geo` に残る。
  地球の上の範囲は正距方位図法で平らな大地に写す（描くときの丸みが同じ図法の逆なので、丸く描くと元の地球の形に戻る）。
  自動保存に入りきらない大きさのときは範囲だけ覚え、次に開いたときに取り寄せ直す。
- **星の丸み**（「星」セクション）：半径（既定は地球の 6371 km）と、丸みを描くかどうか。注視点を中心に地図を球面へ曲げて描くので、
  遠くの地面や海は地平線の向こうへ沈み、高く昇ると丸い星を回り込むように眺められる。雲・霧の標高も星の中心からの距離で測る。
- **近くは細かく遠くは粗く**（`render/GpuTerrain.js`）：リアルタイム表示の地形は GPU で描く四分木（CDLOD）。どの区画も 32×32 の格子を使い回し、
  高さは高さ場のテクスチャから GPU が引く。足元はおよそ 1 m 間隔まで細かくなり、高さ場の格子より細かい所は小さな起伏（`core/terrainDetail.js`、一枚絵と同じ式）で補う。
  区画の境目は頂点を粗い側へ滑らかに寄せてつなぎ、わずかな隙間はスカートで隠す。面の向きと傾きは画素ごとに高さ場から出す（頂点の補間だと区画の境目に線が出る）。地表の色も GPU が塗る（`core/terrainColor.js` と同じ規則）。
- **精度対策**：描くときだけ世界を「注視点の近くの原点（65536 m ごと）」へずらし、GPU には相対座標だけを渡す。深度は対数（足元 1 m から 1 万 km 先まで）。
  ノイズの格子は 2 の累乗の波長にそろえ、原点からの整数の格子番号で計算するので、何千 km 離れても模様が崩れない。
  水面はカメラについて動く同心円の円盤で、画素ごとに視線と海の球面の交点を求めて深度を書く（遠くの粗い三角形で海岸が縞にならない）。
- 一枚絵も同じ：原点を注視点へずらし、地形・木・物体・カメラを同じ式で曲げ、海は球面に沿った円盤。地平線より向こうの区画は作らない。
  パストレーサは near と far の比が大きすぎると光線の計算が壊れて GPU が止まるので、比を 10 万倍までに収めている。

### 歩き回る・宇宙から眺める・夜

- **歩き回るモード**（ツールバーの「🚶 歩く」か G キー）：W/A/S/D で移動、マウスで見回す（画面をクリックするとカーソルを隠す）、Space でジャンプ、Shift で走る、F で飛ぶ／歩くの切り替え（飛ぶときは慣性つきで、なめらかに加速し、離すとすっと滑って止まる）、ホイールで速さ、Esc で元の見回しへ。
  足元は GPU が描く地形と同じ式（細部の起伏まで）で決め、水には浮き、木の幹は通り抜けない。取り込んだ範囲の境目もそのまま歩いて越えられる。飛行の速さは地面からの高さに比例するので、小川の上から大陸の上空まで同じ操作で動ける。
- **音**：歩いている間は、その場で作った音（素材は使わない）が鳴る。風（高い所・速く動くほど強く）、海の近くの波、昼の地上の鳥、足音（地面は「とん」、雪は「さくっ」、水の中は「ぱしゃ」。走ると歩幅が広がり、着地は強く）。
  地図の下の 🔊 か M キーで消せる。
- **地図**：歩いている間は右上に地図（北が上、真ん中の矢印が自分と向き）。取り込んだ地形は衛星写真、そうでなければ起伏の陰影図。
  たたくと広さが変わる（約 500 m → 2 km → 8 km → 全体）。
- **リアルタイム表示の木**：一枚絵と同じ規則・同じハッシュで、同じ所に同じ木が立つ。カメラの周りを 256 m の区画ごとに少しずつ生やし、近く（150 m）は詳しい形、遠くは軽い形で描く。
  水面の映り込みには木を描かない（軽くするため）。
- **宇宙から**：高く昇る（15〜120 km）ほど空が黒くなり、星の縁が青く光り、地表が青くかすむ（視線が通る空気の量から計算）。
- **カメラの道すじ**：操作盤の「カメラの道すじ」で、いまの視点を何か所か足しておくと、▶ でその間をなめらかに（Catmull-Rom）飛ぶ。
  ● で再生しながら録画し、終わったら動画を保存する。道すじはシーン JSON に入る。
- **録画**：ファイル → 画面を録画（動画）で、いま映している画面（景観・地球モード）を WebM で録る（30 fps）。
  画面上の ■ で止めると保存する。地名や地図などの重ねた表示は映らない。
- **季節**：大地の「季節」で、秋は森（緑の濃い所）を紅葉の赤や黄に、春は若葉の明るい緑に、冬は「冬の雪の高さ」より上の
  平らな所に雪（急な斜面は岩のまま）。木の葉の色も変わる（広葉樹は紅葉・冬は枯れ枝）。リアルタイム表示。
- **天気**：大気の「天気」で快晴・晴れ・薄曇り・曇り・霧・かすみ・雨・雷雨・雪をまとめて選ぶ。雨と雪はカメラの周りに降る（歩くときに）。雨の日は地面が濡れて暗く、つややかに。近くの水面には雨粒の波紋が広がる。
  雷雨では、ときどき稲光（2〜3 回またたく青白い光で地面を照らす。夜ほど目立つ）が走り、歩いていれば少し遅れて雷鳴（近いほど早く大きく）が響く。
  「いまの実際の天気と時刻」を選ぶと、その場所のいまの天気（Open-Meteo：雲の量・雨・雪・霧・見通し）と太陽になる。
- **実際の太陽**：操作盤の太陽の「日時から」で日時を選んで「合わせる」と、その場所（取り込んだ地形の中心、ほかは東京）の
  その日時の太陽の高さと方位になる（NOAA の略式）。▶ で時刻を進め続けると、朝焼けから夕暮れ・夜までの移り変わりを眺められる。
- **夜の街の明かり**：取り込むと NASA Black Marble（VIIRS）の夜の明かりも取り寄せ、太陽が沈むと街が光る（リアルタイム表示・一枚絵）。
- **夜**：太陽が沈むと星空が見え、月明かり程度の青い光で地形が見える（一枚絵の空にも同じ光を足す）。
- **周りの地形**：地球から取り込むと、範囲の 6 倍の広さも 2049 格子で取り寄せ、範囲の外にも実際の地形が続いて見える（一枚絵にも入る）。
- **衛星写真の色**：地球から取り込むと、範囲（一辺 512〜4096 画素、約 10〜20 m / 画素）と周りの地形（2048 画素）の衛星写真も
  標高と同時に別のワーカーで取り寄せ、JPEG でシーンに入れる。リアルタイム表示・一枚絵・glb 書き出しの地表の色になり、
  木は写真で森に見える所（暗い緑）にだけ立つ（街・畑・水には立たない）。操作盤の「衛星写真の色」を切ると、標高と傾きから塗る色に戻る。
- **川・湖・海岸線**：一辺 80 km までの範囲では、OpenStreetMap の水域（natural=water・waterway=riverbank の面、
  waterway=river / canal の線、natural=coastline）も標高と同時に取り寄せて格子に焼き込む。
  海か陸かは海岸線で決める（海岸線で区切られた区画ごとに、線の右＝海・左＝陸の印の多数決。濁った湾も干拓地も正しく）。
  海より高い川・湖・ため池は地形を 1 m 掘り下げ、水面として描く（平らで空を映す）。印は PNG でシーンに入れる。
- **建物**：取り込んだ景観を地面から 2 km より低い所から見ると、近く（約 1 km）の建物を立体で出す。OpenFreeMap の
  ベクトルタイル（z14、building 層。© OpenMapTiles © OpenStreetMap contributors）を取り寄せ、外形と高さ（無ければ 6 m）から作る。
  床が 30 m² 未満の小さな建物は省き、影の地図と水面の映り込みには描かない（軽くするため）。操作盤の「建物（3D）」で消せる。
  夜は窓のところどころが灯り、道（transportation 層）に街灯の光の帯が出る。歩くときは建物の壁にぶつかる。一枚絵にも入る。
- **地名**：同じく OpenStreetMap の山（標高つき）・市・町・村の名前を取り込み、景観の上に出す。小さい所ほど近づかないと出さず、
  重なる所は大事なもの（市・高い山）を優先し、手前の山に隠れる地名は出さない。操作盤の「地名を表示」で消せる。
- **標高データの偽の穴**：元の標高タイルには、平野に −2 万 m などの小さな穴の塊がある。タイルを読んだ直後に、
  16 × 16 画素ごとの中央値とばらつきから飛び抜けて低い所（とデータ無しの値）を見つけ、周りの値で埋める（地球モードも同じ）。
- **海と低地**：取り込むとき、海につながっている 0 m 以下の所だけを海にする（干拓地・水田など海につながらない低地は陸）。
  海面の近く（±4 m）では細部の起伏を弱め、水面の深さは地球の半径どうしの引き算をしない式で求める（海抜 1 m の陸でも水と取り違えない）。
  高ズームの標高タイルで 0 m になっている沿岸の海は、粗いデータの海底地形で補う。範囲の縁（一辺の 3%）は周りの地形の高さへ滑らかに寄せ、境目に段差を作らない。
- 一枚絵の丸い星では、平らな三角形が球面より内側にたわむ分（弦のたわみ L²/8R）を補正する：陸の頂点は持ち上げ、水の下の地形は海面の円盤のたわみより深くする。
  上空 20 km より高い所から見下ろすときは、海を「透ける水」ではなく暗い水の色と反射にする（屈折のずれによる同心円の縞を出さない）。

### 地球モード（地球全体）

ツールバーの「🌏 地球」で、地球を丸ごと 1 つの星として眺められる。全大陸・全島・海底が実際の形で出る。

- **地表は四分木**：標高タイル（Web メルカトルの z/x/y）をそのまま四分木の節にし、近い所ほど細かいズーム（最大 15、約 5 m / 画素）に分ける。
  1 区画は 33 × 33 頂点＋縁のすそ（隙間を隠す）。傾きと標高は 256 × 256 の半精度テクスチャで画素ごとに持つ。
- **見えている所だけ取り寄せる**：区画が要るようになったらワーカーが取り寄せ、届くまでは親の区画で代える。粗いもの・近いものから先に、
  見えなくなった所の注文は取り消し、GPU には 360 枚まで置く（古いものから片付ける）。
- **精度**：座標は地球中心（ECEF、Y = 北極）だが、描くときはカメラを原点にする（区画の中心 − カメラ を倍精度で求めてから渡す）。深度は対数。
  宇宙から地上 10 m 余りまで、同じ操作で切れ目なく寄れる。
- **地表の色**：遠く（ズーム 7 まで）は NASA Blue Marble Next Generation（GIBS、パブリックドメイン、約 600 m / 画素）、
  近く（ズーム 8〜14）は Sentinel-2 cloudless 2016（EOX、CC BY 4.0、約 10 m / 画素）の衛星写真。地上近くでは道や畑まで見える。
  起伏の陰影は標高タイルから画素ごとに付ける。「標高と緯度から」に切り替えると、写真を使わず緯度ごとの植生・雪線で塗る。
- **実際の雲**：「雲」の既定は「きのうの実際の雲（衛星）」。NASA GIBS の WMS で地球全体の正距円筒の画像を 2 枚（きのう UTC の VIIRS の写真と、
  雲の無い Blue Marble）取り寄せ、白く色の薄い所のうち、雲の無い地図では白くない所（雪・氷・砂漠を除く）を雲にする。取れなければ手続きの雲。
- **雲**：高さ 6 km の薄い雲の層（手続きの雲。2 段のゆがみで風に引き伸ばされた筋や渦にし、熱帯と中緯度に多く亜熱帯の帯は少なく）。
  画素ごとに視線が雲の層を通る所を求めて重ね、地表には太陽からの雲の影を落とす。遠いほど細かい段を省く。画面上部の「雲」で消せる。
- **夜の街の明かり**：夜の側には NASA Black Marble（VIIRS、2016 年）の明かりが灯る（夜の側のタイルだけ取り寄せる）。
- **大気**：一回散乱（レイリー＋ミー）。空も地表のかすみも同じ式で、宇宙からは青い縁、地上からは青空と夕焼けになる。夜の側は暗く、星空が見える。
- **太陽**：「シーンの太陽」は見ている所の空にシーンの太陽（高さ・方位）を置く。「いまの実際の太陽」は現在の日時から太陽の真下の点を求める（昼夜の境が実際の位置に出る）。
- **操作**：ドラッグで移動、ホイールでカーソルの先へ寄る、右ドラッグ（Shift / Ctrl ＋ドラッグ）で向きと傾き、ダブルクリックでそこへ寄る、
  W/A/S/D・矢印で移動、Q/E で向き、R/F で傾き、+/− で寄る・離れる、Esc で戻る。地名で検索して飛べる（遠い所へは山なりに飛ぶ）。
  タブレット・スマートフォンでは、1 本指で移動、2 本指でつまんで寄る（指の中ほどへ）・ひねって向き・上下にそろえて動かして傾き、2 回たたいてそこへ寄る。
- **右側のボタン**：方位磁針（向きに合わせて回る。押すと北を上に・真下を見る）、寄る・離れる、いまいる場所へ（端末の位置情報）。
- **ここに降りて歩く**：見ている所を 12 km 四方ほど取り込み（衛星写真の色つき）、その中心の地面に立って、地球モードで見ていた向きのまま歩き始める。
- **重さに合わせた画質**：1 秒ごとの平均の描画間隔を見て、解像度の倍率を自動で上げ下げする（目安 30〜50 fps。タブレットでも動くように）。
- **景観に取り込む**：「ここを景観に取り込む」で、いま見ている辺り（見ている距離の 1.6 倍四方、4 km〜3000 km）を
  「地球の地形を取り込む」画面に渡す。取り込めば、その場所を歩いたり一枚絵にしたりできる。
- 極（緯度 ±85° より先）はメルカトルのタイルが無いので、ふたの面で閉じる（北は海氷、南は南極の氷床の高さ）。
- 視点は自動で残る（実在の地球を眺める道具なので、シーン JSON には入れない）。

### 物体と素材

- 形：球・立方体・円柱・円錐・角錐・トーラス・環（平たい環。惑星の環に）。大きさはメートルで、1 m〜100 km まで。
- 「天体」ボタンは、視線の先の遠く・画面の上寄りに直径が地形の 1.2 倍ほどの星を置く。天体はかすみで消えず、影も落とさない。
  環を同じ位置に置いて傾ければ、土星のような星になる。
- 素材は見本（石・苔むした岩・大理石・溶岩の星・青い惑星・ガス惑星・月・氷・黄金・鏡面・ガラス・恒星・市松・縞瑪瑙）から選び、
  模様（単色・大陸と海・ガスの縞・溶岩・大理石・岩肌・細胞・クレーター・縞・市松・画像）、色、細かさ、模様の種、凹凸、粗さ、金属、発光、透けを調整できる。
- 模様は手続き的に作るテクスチャ（色・法線・発光の 3 枚）。継ぎ目なく一周するので、球に貼っても縫い目が出ない。計算は Web Worker。
- 「画像」模様では手持ちの画像を貼れる（長辺 1024px に縮めてシーン JSON に埋め込む）。

作業中のシーンはブラウザの localStorage に自動で残る（消えても動作には影響しない）。
リアルタイム表示は重さに応じて解像度を自動で上げ下げする（目安 30〜50 fps）。
起動中は読み込み画面を出し、部品の読み込みに失敗したときや WebGL2 が使えないときは理由を表示する。
予期しないエラーは画面上部に知らせる。一枚絵を描いている間はファイルの読み込みや Delete などの操作を受け付けない（Esc で中止）。

## 設計：シーン = データ、描画 = その解釈

```
            ┌──────────── シーン JSON（src/core/schema.js）────────────┐
            │ terrain / water / sun / atmosphere / camera / render     │
            └───────────────▲───────────────────────┬──────────────────┘
       UI（ui/Panel.js）が  │ store.set(path)        │ subscribe(変更パス)
       パスで書き込むだけ   │                        ▼
                 ┌──────────┴──────┐   ┌────────────────────────────┐
                 │ core/store.js   │   │ render/RealtimeRenderer.js │ ← リアルタイム表示（今）
                 └─────────────────┘   │   Sky / Water シェーダ      │    歩き回るモード（予定）
                                       └─────────────┬──────────────┘
     core/（Three.js 非依存）                        │ 共通部品
       heightfield.js 高さ場の生成                   ▼
       terrainColor.js 地表色の焼き込み    three/terrainMesh.js  高さ場 → メッシュ
       png16.js        16bit PNG 読み書き  three/portableScene.js 標準 PBR だけのシーン
       sun.js          太陽・大気の計算      ├→ io/gltf.js       .glb 書き出し
       skyModel.js     空の HDR（CPU 版 Sky） render/StillRenderer.js 一枚絵（パストレース・ノイズ除去・空気遠近）
       terrainLod.js   近いほど細かい地形    workers/lodWorker.js
       erosion.js      侵食                  tonemap.js  AgX / ACES / Radiance HDR 書き出し
       objects.js      物体・素材の定義      three/objectLayer.js  物体 → メッシュ（表示と書き出しで共有）
       texgen.js       模様テクスチャの生成  three/TextureService.js 模様をワーカーで作り使い回す
     workers/terrainWorker.js（重い計算）    └→ 高画質一枚絵モード（予定：パストレーサ等の入力）
```

- **シーン JSON が正本**。描画器・書き出しはすべてこれを読むだけで、互いを知らない。
  一枚絵モードや歩き回るモードは「同じ JSON を別の描画器で解釈する」形で足せる。
- `core/` は Three.js に依存しない（ワーカーや Node でもそのまま動く）。
- 重い処理（ノイズ生成・ハイトマップ解釈・地表色）は Web Worker。計算中に来た変更は最新の1件にまとめる。
- 起伏の高さ・標高はメインスレッドで即座に形を変え、色は後追いで届く。
- 地表の色は CPU でテクスチャに焼く。リアルタイム表示と glb 書き出しで同じ絵になる。

### シーン JSON（version 1）の主な項目

| パス | 意味 |
|---|---|
| `terrain.mode` | `noise`（手続き生成）か `heightmap`（画像） |
| `terrain.size` / `resolution` | 一辺の長さ (m) / 頂点数（129・257・513・1025） |
| `terrain.heightScale` / `baseHeight` | 標高 = baseHeight + 正規化高さ(0..1) × heightScale |
| `terrain.noise.*` | seed・frequency（山の数）・octaves・persistence・lacunarity・ridged・warp・valley・falloff |
| `terrain.heightmap` | `{ id, name, png(16bit PNG の dataURL), width, height }` |
| `terrain.palette.*` | 低地・高地・岩・雪・水辺の色、雪線、岩の出る傾斜 |
| `vegetation.*` | trees（森の量）・treeHeight・conifer（針葉樹の割合）・grass（草）・seed |
| `water.*` | enabled・level (m)・color・distortion・waveScale |
| `sun.*` | elevation（度）・azimuth（北から東回りの度）・intensity |
| `atmosphere.*` | turbidity・rayleigh・mieCoefficient・mieDirectionalG・haze・exposure・ambient |
| `camera.*` | position・target・fov |
| `objects[]` | 物体。`{ id, name, type, position, rotation(度), scale(m), celestial, castShadow, material }` |
| `objects[].material` | `{ preset, pattern, color, color2, glowColor, scale, seed, bump, roughness, metalness, glow, transmission, image }` |
| `render.still.*` | 一枚絵の幅・高さ・サンプル数（Blender スクリプトにも渡る） |

同じ seed・同じ設定なら必ず同じ地形になる。解像度を上げると、格子で表せる細部だけが増える（大きな形は変わらない）。

### 座標の約束

- Y が上、**北 = −Z、東 = +X**、単位はメートル（glTF と同じ）。Blender では北 = +Y、東 = +X、上 = +Z になる。
- 高さ場とハイトマップ画像は **画像の上 = 北**。

## 他ソフトとの連携

### glTF（.glb）書き出し

| ノード | 中身 |
|---|---|
| `Terrain` | 地形メッシュ（法線・UV 付き）＋ 地表色テクスチャ（PNG 埋め込み）の PBR 素材 |
| `Water` | 地形の 3 倍の板。透過（KHR_materials_transmission）・屈折率 1.333・ボリューム吸収の水素材 |
| `Sun` | 平行光源（KHR_lights_punctual）。Blender の読み込みで W/m² に換算される強さで出力 |
| 物体の名前 | 物体ごとのメッシュ。模様は色・法線・発光テクスチャ（PNG 埋め込み）、発光は KHR_materials_emissive_strength、透けは transmission。同名は `_2` などで区別 |
| `Camera` | 透視カメラ（縦横比は「一枚絵」の幅・高さ） |
| scene.extras.`kuniumi` | シーン JSON 一式（埋め込みハイトマップ画像は除く） |

### glTF 読み込み

- KUNIUMI が書いた glb なら extras から設定を復元する。
- **地形は常にメッシュの形から取り込む**（真上からの正射影で各格子点の最高点を測る）。
  Blender で地形を彫り直して glb で戻せばそれが反映され、他ソフトで作った地形メッシュもそのまま地形になる。
  取り込んだ地形は「ハイトマップ」扱いになる。ノイズ設定は残っているので、生成方法を「ノイズ」に戻せば手続き地形に戻る。
- `Water`（名前に water/水）があれば水位に、平行光源があれば太陽の向きに、カメラがあれば視点にする。
- 物体は、ノードの extras（`kuniumiId`）か書き出し時の名前で見分けて地形から除き、位置・回転・大きさを読み戻す
  （Blender で動かした結果が反映される）。素材は KUNIUMI の設定（scene.extras）から復元する。
- Blender から書き出し直すときは「Include → Custom Properties」を入れると KUNIUMI の設定ごと戻せる。入れない場合は、いま開いているシーンの物体と名前で照合して位置を戻す（素材はいまのシーンのまま）。

### Blender でそのままレンダリングする

1. 「glb 書出」と「Blender 用 .py」を押し、2つを同じフォルダに置く（ファイル名はそろっている）。
2. Blender の Scripting タブでその .py を開いて実行（または `blender --python 名前_blender.py`）。
   - glb を読み込み、太陽の向きに合わせた物理空（Nishita / Multiple Scattering）をワールドに設定
   - 大気の濁り・青さを近似で反映、Cycles・解像度・サンプル数・カメラを設定
3. F12 でレンダリング。明るさはスクリプト冒頭の `SKY_STRENGTH`、空の太陽円盤を使うかは `USE_SKY_SUN` で調整。

スクリプトなしでも、glb を File → Import → glTF で読めば地形・水・太陽・カメラは入る（空だけが無い）。

### ハイトマップ（16bit PNG）

- グレースケール 16bit、画素値 0..65535 → 標高 `baseHeight .. baseHeight + heightScale`、画像の上が北。
- PNG の tEXt `kuniumi` に実寸（size・heightScale・baseHeight・waterLevel）を JSON で入れている。KUNIUMI で読み込むと実寸ごと復元される。
- Blender で使う場合：Grid（一辺 = size、細分多め）に Displace モディファイア、テクスチャにこの PNG（色空間 **Non-Color**、座標 UV）、
  強さ = heightScale、中間レベル = 0、オブジェクトの Z = baseHeight。
- World Machine・Gaea・Unreal・Unity など 16bit PNG ハイトマップを受け付けるソフトとも同じ形式でやり取りできる。

## 確認済みのこと・注意

- 描画の重さ（この PC：Ryzen 5 5560U 内蔵 GPU、950×708 画素、霧・雲・影・木すべてあり、1 フレームの GPU 時間）：
  | 場面 | ms |
  | --- | --- |
  | 既定の島を見渡す | 21 |
  | 森の中に立つ（視野の中の木 約 5 千本＋近くの木） | 28 |
  | 富士山周辺（2049²＋周りの地形）を空から | 23 |
  | 富士山の麓に立つ | 20 |
  | 宇宙から星を眺める | 12 |
  （3 回測ってそろった値。どの場面も 30 fps 以上。さらに重いときは表示の解像度を自動で下げる）
  変更後に、木の影が地面にくっきり落ちること・水面に島が映ることを画面で確認済み。
  軽くするための工夫：視野の外の遠い木は描かない、水面の映り込みは 512 画素で木を省く、太陽の影の地図は 2048 画素でカメラの見ている辺りだけ。
- 自動テスト（`npm test`、36 件）：地図の投影・タイル座標・丸みの式・沿岸の海底の補い・縁のなじませ、
  木が一枚絵とリアルタイム表示で同じ所に同じ高さで立つこと、歩く（坂・ジャンプ・飛行・当たり判定）、
  GPU 地形の高さ・光線の交点・数千 km の大地での区画の数と細かさ、などを確かめている。
